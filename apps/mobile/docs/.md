# Cafe POS — Complete Screen List & User Flows
**Purpose:** Finalize every screen needed before starting UI design, so nothing is missed
and design work doesn't have to be redone mid-way.

---

## Part 1 — Where to Find Design Inspiration (proper way)

Random Google Images searching wastes time and gives inconsistent results. Use these in
this order:

### 1. Mobbin.com — the best source, use this first
Mobbin has real, current screenshots from live apps, organized by flow (not just single
screens). Search/filter by:
- Category: **"Point of Sale"**, **"Food & Drink"**, **"Restaurant"**
- Specific flows to study: "Checkout", "Onboarding", "Order Tracking", "Dashboard"
- Look at Indian apps specifically: Zomato, Swiggy, PhonePe, Paytm (for payment UI),
  BigBasket (for cart/checkout patterns) — these are what your target users already know,
  so borrowing familiar patterns from them reduces learning curve

### 2. Study the actual competitor — install Petpooja's app
This is the single most useful research step. Download Petpooja's app (or watch their
demo videos on YouTube), and specifically note:
- Where the UI feels slow or cluttered — that's your opportunity
- How many taps it takes to complete a basic order — try to beat that number
- What their KDS screen looks like from a distance (simulate kitchen conditions —
  step back from your screen, is it still readable?)

### 3. Dribbble.com — for visual style/color inspiration only
Search "restaurant POS UI", "KDS dashboard", "cafe billing app". Useful for color
palettes and micro-interactions, but many Dribbble shots are concept work that was never
built and tested — don't copy layouts blindly from here, only use for visual style ideas.

### 4. Behance.net — for full case studies
Search "restaurant management app case study" or "POS UX case study" — designers often
post their full research + wireframes + reasoning, which is more useful than a single
pretty screenshot because you see *why* they made each decision.

**Practical approach:** Spend one focused session (60–90 minutes) on Mobbin + Petpooja
only. Screenshot 10–15 screens you like. Don't endlessly browse — decision fatigue kills
momentum.

## Part 2 — Complete Screen List (every screen, by role)

### A. Shared / Auth Screens (all roles pass through these)
1. **Splash screen** — logo, brief loading
2. **Login screen** — email + password
3. **OTP verification screen** — 6-digit input, resend button, countdown timer
4. **Role-based redirect** — invisible screen/logic, routes to Cashier/Chef/Admin home
   based on JWT role after login

*Gap to flag: there is no "Forgot Password" flow in the backend yet — not built in
Auth module. Needs a decision: build it now, or defer (staff accounts are created by
Owner/Manager, so an Owner could reset a forgotten password manually via a future admin
tool instead of self-service reset — worth discussing before deciding it's needed for
launch).*

### B. Cashier Screens (core revenue-generating flow)
5. **Billing / Home screen** — category tabs at top, product grid below, cart panel
   (side panel on tablet, bottom sheet on phone)
6. **Product variant/addon selector** — modal, shown when a product with variants/addons
   is tapped (e.g. choosing Small/Large, Extra Cheese)
7. **Cart / Order summary** — line items, quantities editable, running total, tax shown

11. **Active orders list** — all of today's orders for the outlet, filterable by status
    (Pending/Preparing/Ready/Served), tap to view detail
12. **Order detail view** — full item list, status, payment status; "Mark as Served"
    action here for items that are Ready

## Part 3 — User Flows (step by step, how each role's day actually works)

### Flow 1 — Cashier's Shift
1. Opens app → Login screen → enters email/password
2. Lands on Billing/Home screen (role-based redirect sent them here)
3. Customer orders — Cashier taps category tab, taps product
4. If product has variants/addons → modal opens → Cashier selects → adds to cart
5. Repeats for all items in the order
6. Taps Cart → reviews → if Dine-In, selects a table from Table Selector
7. Taps Checkout → selects payment method
   - If UPI: QR code shown, customer scans and pays, Cashier confirms
   - If Cash: enters amount received, app shows change to return
8. Order Confirmation screen → optionally prints/shares bill
9. Order automatically appears on Chef's KDS board in real time (already proven working)
10. Later: Cashier checks Active Orders list, sees an order marked "Ready" (pushed via
    Socket.io from Chef's action) → taps "Mark as Served"

### Flow 2 — Chef's Shift
1. Opens app → Login → lands directly on KDS board (no other screens needed)
2. New order appears instantly (Socket.io push) as a card
3. Chef taps the card → sees items, any special notes (e.g. "Less sugar") highlighted
4. Taps status button per item: Pending → Preparing → Ready
5. Card visually ages (yellow at 8 min, red at 15 min) if not completed — keeps kitchen
   aware of what's falling behind
6. Once all items in an order are Ready, order effectively leaves the active board
   (moves to Cashier's "ready to serve" list)

### Flow 3 — Owner/Manager's Day
1. Opens app → Login → lands on Dashboard
2. Checks daily summary card — sales so far, order count
3. Sees a low-stock alert banner (e.g. "Coffee Beans running low") → taps through to
   Inventory → adjusts quantity or notes to restock
4. Later, adds a new seasonal menu item — goes to Menu → Product create → sets price,
   variants, marks available
5. End of day, checks Audit Logs to review any voided orders and reasons
6. Periodically checks Subscription screen to confirm billing is current

### Flow 4 — Customer (QR ordering, no app)
1. Scans QR code on table → opens web browser directly to `/order/{outlet-slug}`
2. Browses menu, taps a product, selects variant/addon if applicable, adds to cart
3. Reviews cart → places order → sees "Pay at Counter" confirmation with order number
4. Order appears on Chef's KDS in real time exactly like a Cashier-placed order
   (already proven — `cashierId: null` distinguishes it)
5. Customer's browser polls the order status page — watches it move from
   Preparing → Ready
6. Customer pays at the counter when collecting/served; Cashier marks payment complete
   from their side

## Part 4 — What This Means for Build Order

Once the visual design direction is picked, the natural build sequence (screens that
unlock testing the next ones) is:

1. Auth screens (Login, OTP) — needed to test everything else
2. Cashier Billing + Cart + Checkout — the core money-making flow, build and test first
3. Chef KDS — pairs directly with #2 for the real-time loop
4. Admin Menu + Inventory management — needed to populate real data for #2 and #3 to
   use, but can be built in parallel/after since test data already exists via Postman
5. Admin Dashboard, Staff, Tables, Audit, Settings — lower urgency, needed for
   completeness but not blocking the core loop
6. Web customer ordering — last, since it reuses patterns already proven on mobile
