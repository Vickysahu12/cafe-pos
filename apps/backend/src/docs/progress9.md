## 3. Bill on WhatsApp: how it works

```
Cashier collects payment (Checkout or Order screen)
  → "Send bill on WhatsApp" (green button / option in the success alert)
  → types the customer's mobile number (validated: 10 digits, starts 6–9; "+91 98765-43210" accepted)
  → café's OWN WhatsApp opens with the message ready:
       "Thank you for visiting Brew House Café! 🙏
        Your bill #12: ₹640.50
        View your bill: https://order.billraw.in/bill/<orderId>"
  → customer taps the link → receipt page (can Save as PDF)
```

**Privacy and security** (smoke-tested):
- **The customer's number never reaches our server.** The app builds a `wa.me` link on the cashier's phone. Nothing is stored (DPDP-friendly).
- The bill link uses the order's **UUID v4** (122 random bits, unguessable). Non-UUID IDs never hit the database.
- The public API returns only bill fields via Prisma `select`; no `id`, `outletId`, `cashierId` or notes.
- No money flow at all (only showing a bill).
- "Share another way" (Android share sheet) is there for customers who don't want to give a number.

## 4. Files

**Backend**
- `public-menu.service.ts`: `getPublicBill(orderId)`: UUID check → `findUnique` with a minimal `select` (café name/address/phone/GSTIN/slug, items with unit price, totals, payment status/method, table).
- `public-menu.controller.ts`: `getBill`. A non-UUID ID calls `next()`, so if a café's slug is ever `bills`, `/public/bills/menu` still reaches its menu.
- `public-menu.routes.ts`: `GET /public/bills/:orderId` (registered before the `/:slug/...` routes).

**Web (`order.billraw.in`)**
- `app/bill/[orderId]/page.tsx`: a **server-rendered** receipt (fast on 4G):
  - café header (monogram, address, phone, GSTIN)
  - status badge (Paid · UPI / Not paid yet / Cancelled / Refunded)
  - date and time in **IST**
  - items with "qty × unit price"
  - totals
  - "Bill generated by BillRaw" (free marketing on every bill)
  - Labelled **"Bill", not "Tax Invoice"**: GST tax invoices have extra rules (HSN/SAC, CGST/SGST split).
  - **WhatsApp link preview** via `generateMetadata`: "Bill #12 · Brew House Café" / "₹640.50 · Paid · UPI · 5 Oct 2026".
  - React `cache()` so the metadata and the page fetch the bill only once.
  - Print CSS hides the buttons.
- `app/bill/[orderId]/PrintButton.tsx`: "Save as PDF" (`window.print`, the only client component).
- `lib/api.ts`: `PublicBill` type + `getBill()`.

**App**
- `components/orders/ShareBillSheet.tsx` (new): bottom sheet + `SendBillButton` (WhatsApp green), `normalizeIndianMobile()`, `wa.me` link, share-sheet fallback.
- `app/(cashier)/orders/[id].tsx`: the green button on PAID, non-cancelled orders, and a "Send bill on WhatsApp" option in the "Payment Collected" alert. The Owner/Manager order screen re-exports this, so they get it too.
- `app/(cashier)/checkout.tsx`: passes `netAmount` **from the pay response** to the confirmation screen.
- `app/(cashier)/confirmation.tsx`: the "Send bill on WhatsApp" button above "New Order".
